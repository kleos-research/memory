MCP reference

The candidate public contract publishes exactly two model-callable MCP tools over stdio revision 2025-11-25. Everything else remains outside the agent tool list.

Exact local binding. Engine 988192ac9677…, public contract a2357ed6c00e…, macOS arm64 only. This is contract and functional evidence, not a production signature or availability claim.

Download the machine-readable candidate MCP reference.

search

Supply exactly one of query or memory_id. A query performs ranked retrieval and records an exposure; ledger accepts only true. Use a small protocol-defining top_k (normally about 5) and a bounded maximum_context_bytes. Ranked results appear under selected_hits. An addressed read returns the memory at top level and refuses ranking controls.

{"query":"What constraints govern the release?","top_k":5,"ledger":true}

remember

mode is required and is create, update, or delete. Create/update content begins with an H1 and carries a semantic delta with a required title and at least one fact. Every fact endpoint is declared with n, kind, and the required is gloss. Predicates are snake_case. Update/delete use memory_id and expected_version_id. Batching accepts at most 20 creates and does not share semantic fields between items.

Lifecycle

Clients keep one stdio process alive across calls, negotiate MCP once, enforce a startup deadline, cancel cleanly, bound stderr, and tear down without an orphan. DX-07 locally verifies persistent Python and TypeScript sessions; framework integrations do not run a second hidden retrieval.

Not agent tools

Feedback, lifecycle/import, maintenance, ontology, and diagnostics are controller/operator operations. Public search does not return the handle required for feedback, so there is no supported public agent-attribution path. Historical names are documented only on the migration page.
